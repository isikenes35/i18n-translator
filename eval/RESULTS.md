# Eval results

Each test runs the same task twice: once without the skill, and once with the agent told to read `SKILL.md` first. Every agent session starts fresh, so nothing carries over between sessions except the files on disk. The metrics were written in the grader scripts before the runs, and the graders do not use the skill's own validator. Raw grader output is in `results/`.

## Small test (`small/`)

A React + i18next app with a half-finished Russian translation. It has 30 English keys with plurals, placeholders and an HTML tag, plus two keys whose meaning depends on the code: `actions.post` is a publish button and `labels.order` is a sort dropdown.

- Session 1: complete `locales/ru/common.json`.
- Session 2: create `locales/ru/features.json`.

| Model | Runs per condition | Translation errors, no skill | Translation errors, skill | New file registered in `src/i18n.js`, no skill | Same, skill |
|---|---|---|---|---|---|
| gemini-4-hydrogen-medium | 3 | 0 | 0 | 1/3 | 0/3 (see note) |
| gemini-4-hydrogen-low | 3 | 1 run dropped all `_other` plural forms | 0 | 0/3 | 3/3 |
| Claude Haiku (run as a Claude Code subagent) | 3 | 0 | 0 | 0/3 | 3/3 |

Translation errors cover missing keys, missing Russian plural forms, broken placeholders or tags, untranslated values, changed existing translations, inconsistent terms, and the wrong meaning for `post` or `order`.

Note: the hydrogen-medium runs used an earlier version of the skill that did not yet have the step for registering new files.

## Scale test (`scale/`)

Generated by `make_fixture.py`: the same app with 6 namespaces and 221 English keys, built around three domain terms (workspace, board, ticket). The existing Russian file already uses "Заявки" for tickets. The work is split over 3 fresh sessions, each covering 2 files.

Model: gemini-4-hydrogen-low, 2 runs per condition.

| Metric | No skill, run 1 | No skill, run 2 | Skill, run 1 | Skill, run 2 |
|---|---|---|---|---|
| Term errors | 98/281 | 92/269 | 0/281 | 0/281 |
| Missing keys | 0 | 6 | 0 | 0 |
| New namespaces registered | 0/5 | 0/5 | 5/5 | 5/5 |
| `settings.post` as a verb ("Опубликовать") | no | yes | yes | yes |

The term errors without the skill come from later sessions. The agent drops the existing "заявка" and writes "тикет" or "задача" for "ticket" instead. With the skill, the agent stores the terms in `i18n-glossary.json`, and later sessions read that file.

Same test with a larger model, gemini-4-hydrogen-high, 2 runs per condition:

| Metric | No skill, run 1 | No skill, run 2 | Skill, run 1 | Skill, run 2 |
|---|---|---|---|---|
| Term errors | 0/281 | 0/281 | 0/281 | 0/281 |
| Missing keys | 0 | 0 | 0 | 0 |
| New namespaces registered | 0/5 | 0/5 | 5/5 | 5/5 |

The larger model kept the terms consistent without the skill. The skill still made the difference in registering new files.

## Limits

- The runs are few: 2 or 3 per condition.
- Only one target language (Russian) and one framework (i18next) were tested.
- The scale test used two models from one family (gemini-4-hydrogen-low and -high).
- The Haiku runs were done through Claude Code subagents, not with `run_eval.py`.

## Run it yourself

The run scripts use the Antigravity CLI (`agy`).

```bash
py -3 small/run_eval.py gemini-4-hydrogen-low 3
py -3 small/grade.py small/runs/gemini-4-hydrogen-low/*
py -3 scale/make_fixture.py
py -3 scale/run_scale.py gemini-4-hydrogen-low 2
py -3 scale/grade_scale.py scale/runs/gemini-4-hydrogen-low/*
```
